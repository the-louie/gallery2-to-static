# SEC-03: Document React DOM-Only Contract for BBCode Parser escapeHtml()

**Date:** 2026-03-28
**Severity:** High | **OWASP:** CWE-79 (XSS)
**Affected files:**
- `frontend/src/utils/bbcode.ts` (lines 174-180)
- `frontend/src/utils/bbcode.test.ts`

---

## Problem Statement

The `escapeHtml()` function in `frontend/src/utils/bbcode.ts` is a no-op pass-through that returns its input unchanged:

```typescript
function escapeHtml(text: string): string {
  return text;
}
```

This function is called 7 times within `parseBBCodeInternal()` to wrap all text segments pushed into the `result` array (literal brackets, plain text between tags, unmatched tag text, and trailing text). The function name implies HTML escaping but performs none.

This is **intentionally correct** for the current usage pattern: `parseBBCode()` returns `React.ReactNode` values (strings and React elements), which React's DOM renderer automatically escapes when inserting into the DOM. Implementing actual HTML entity escaping (`&` -> `&amp;`, `<` -> `&lt;`, etc.) would cause double-encoding, because React would then re-escape the already-escaped entities, resulting in literal `&amp;` displayed to users.

### The Risk

The risk is **not in the current code** but in future misuse. If a developer were to:
1. Use `parseBBCode()` output in `dangerouslySetInnerHTML`
2. Serialize `parseBBCode()` output to an HTML string for non-React contexts
3. Use the output in server-side rendering without React's escaping

...then the no-op `escapeHtml()` would provide no XSS protection, and raw `<script>` tags or other HTML in user content would be injected.

### Current Safety Evidence

The codebase already guards against this:
- **No `dangerouslySetInnerHTML` in production code**: A search of `frontend/src/` shows zero non-test usages. All occurrences are in test files that *assert* it is NOT used.
- **All callers render via React JSX**: The 10 call sites across 6 components (`AlbumDetail`, `AlbumCard`, `Breadcrumbs`, `Layout`, `Lightbox`, `RootAlbumListBlock`) all embed `parseBBCodeDecoded()` output directly in JSX expressions like `{parseBBCodeDecoded(album.title)}`.
- **Existing XSS tests pass**: Tests in `bbcode.test.ts` verify that `<script>` tags in BBCode content are rendered as text, not executed.
- **Separate `escapeHtml` exists in `searchHighlight.ts`**: That file has its own properly-escaping `escapeHtml()` (using `div.textContent`/`div.innerHTML`) for HTML string output contexts. The two functions serve different purposes.

### Fix Strategy

The correct fix is documentation, not implementation:
1. Add a clear JSDoc warning to `escapeHtml()` explaining the intentional no-op and the React DOM-only contract
2. Add a `@security` JSDoc tag warning against non-DOM usage
3. Update the module-level JSDoc to mention the React DOM escaping dependency
4. Add a `@see` reference pointing to `searchHighlight.ts` for the actual HTML-escaping variant
5. Add a test that explicitly documents and verifies the contract

Implementing actual escaping would be **harmful** because it would double-encode text when React renders it, breaking display of characters like `&`, `<`, `>`, and `"` in album titles and descriptions (e.g., a title containing `Tom & Jerry` would display as `Tom &amp; Jerry`).

### Section 2.1: Update `escapeHtml()` Function Documentation

#### Task 2.1.1: Replace the `escapeHtml()` JSDoc comment
**File:** `frontend/src/utils/bbcode.ts`

Replace the existing JSDoc (lines 174-180):
```typescript
/**
 * Pass-through for text in React. React escapes when rendering to DOM,
 * so we must not pre-encode (e.g. ' to &#039;) or entities display literally.
 */
function escapeHtml(text: string): string {
  return text;
}
```

With an expanded JSDoc that explicitly documents the security contract:
```typescript
/**
 * Intentional no-op pass-through for text content in React rendering context.
 *
 * This function is deliberately a no-op because parseBBCode() returns
 * React.ReactNode values that React's DOM renderer automatically escapes
 * when inserting into the DOM. Implementing actual HTML escaping here would
 * cause double-encoding (e.g. '&' would display as '&amp;' to the user).
 *
 * @security WARNING: This function provides NO HTML escaping. The output of
 * parseBBCode() is ONLY safe when rendered through React's standard JSX
 * rendering pipeline (e.g. `{parseBBCode(text)}`). Do NOT use parseBBCode()
 * output in:
 * - dangerouslySetInnerHTML
 * - Manual HTML string concatenation
 * - Non-React rendering contexts (e.g. server-side HTML templates)
 * - Any context that does not apply its own output encoding
 *
 * For HTML string contexts that require actual escaping, see the escapeHtml()
 * function in searchHighlight.ts which uses DOM-based escaping.
 *
 * @param text - Text content to pass through unchanged
 * @returns The input text unchanged (React handles escaping at render time)
 */
function escapeHtml(text: string): string {
  return text;
}
```

## Phase 3: Testing

### Section 3.1: Add Contract-Documenting Tests

#### Task 3.1.1: Add test verifying React DOM escaping handles XSS
**File:** `frontend/src/utils/bbcode.test.ts`

Add a new `describe` block within the existing `'Security - XSS prevention'` section that explicitly documents the React DOM escaping contract:

```typescript
describe('SEC-03: React DOM escaping contract', () => {
  it('relies on React DOM escaping for text content (escapeHtml is intentional no-op)', () => {
    // parseBBCode returns React.ReactNode, not HTML strings.
    // React escapes text content when rendering to DOM.
    // This test verifies the contract works end-to-end.
    const result = parseBBCode('Text with <img src=x onerror=alert(1)> injection');
    const { container } = render(<>{result}</>);
    // The raw HTML should appear as text, not as an element
    expect(container.textContent).toContain('<img src=x onerror=alert(1)>');
    expect(container.querySelector('img')).not.toBeInTheDocument();
  });

  it('escapes HTML in BBCode content rendered through React', () => {
    const result = parseBBCode('[b]<div onmouseover="alert(1)">hover</div>[/b]');
    const { container } = render(<>{result}</>);
    const strong = container.querySelector('strong');
    expect(strong).toBeInTheDocument();
    // The div should be text content, not a DOM element
    expect(strong?.textContent).toContain('<div onmouseover="alert(1)">hover</div>');
    expect(container.querySelector('div[onmouseover]')).not.toBeInTheDocument();
  });

  it('escapes ampersands in text without double-encoding', () => {
    const result = parseBBCode('Tom & Jerry');
    const { container } = render(<>{result}</>);
    // Should display as "Tom & Jerry", not "Tom &amp; Jerry"
    expect(container.textContent).toBe('Tom & Jerry');
  });

  it('escapes angle brackets in text without double-encoding', () => {
    const result = parseBBCode('x < y > z');
    const { container } = render(<>{result}</>);
    expect(container.textContent).toBe('x < y > z');
  });
});
```
