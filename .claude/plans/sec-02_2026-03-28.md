# SEC-02: Fix BBCode Parser URL Scheme Validation

**Date:** 2026-03-28
**Severity:** High | **OWASP:** CWE-79 (XSS)
**Affected file:** `frontend/src/utils/bbcode.ts`

---

## Problem Statement

The BBCode parser validates URLs in `[url=...]` and `[url]...[/url]` tags using only a regex prefix check:

```typescript
const URL_SCHEME_REGEX = /^https?:\/\//i;
```

This regex confirms the string starts with `http://` or `https://` but does not validate URL structure. It allows malformed or deceptive URLs to pass and be rendered as clickable `<a href="...">` links:

| Input | `URL_SCHEME_REGEX.test()` | Actually valid? |
|-------|--------------------------|-----------------|
| `https://example.com` | `true` | Yes |
| `https://` | `true` | **No** — no host |
| `https:// ` | `true` | **No** — whitespace host |
| `https://example.com\n@evil.com` | `true` | **Ambiguous** — newline in URL |
| `http://[malformed` | `true` | **No** — broken IPv6 |

### Attack Surface

The validated URL is used in two places that set `href` attributes:

1. **`parseBBCodeInternal()` (line 420-425):** Creates `React.createElement('a', { href, ... })` — the `href` ends up as a DOM attribute on an anchor element.
2. **`extractUrlFromBBCode()` (lines 520-528):** Returns the URL which is rendered in `RootAlbumListBlock.tsx` line 164 as `<a href={extUrl.url}>`.

While React prevents `javascript:` scheme execution in `href` attributes (as of React 16.9+), malformed URLs can still cause:
- Navigation to unexpected destinations
- Browser-specific URL parsing quirks leading to open redirects
- Confusing UI when displaying broken URLs to users

### Where URL_SCHEME_REGEX Is Used (5 call sites, all in bbcode.ts)

1. **Line 216** — `parseAttribute()`: `[url=value]` where value has no `=` sign (bare attribute)
2. **Line 245** — `parseAttribute()`: `[url href=value]` or `[url url=value]` (named attribute)
3. **Line 415** — `parseBBCodeInternal()`: `[url]content[/url]` where content is used as href
4. **Line 520** — `extractUrlFromBBCode()`: `[url=rawUrl]label[/url]` extraction
5. **Line 528** — `extractUrlFromBBCode()`: `[url]rawUrl[/url]` extraction

## Phase 2: Implementation

### Section 2.1: Add URL Validation Function

#### Task 2.1.1: Create `isValidHttpUrl()` helper function
Add a private helper function in `frontend/src/utils/bbcode.ts`, replacing the `URL_SCHEME_REGEX` constant.

**Location:** Replace lines 154-155 (the `URL_SCHEME_REGEX` declaration) with the new function.

```typescript
/**
 * Validate that a string is a well-formed http or https URL.
 * Uses the URL constructor for structural validation and restricts
 * to http/https schemes to prevent javascript:, data:, etc.
 */
function isValidHttpUrl(value: string): boolean {
  try {
    const parsed = new URL(value);
    return parsed.protocol === 'http:' || parsed.protocol === 'https:';
  } catch {
    return false;
  }
}
```

Design decisions:
- **Private function** (not exported) — same scope as the constant it replaces
- **`URL` constructor** does the structural validation: rejects missing host, invalid characters, malformed IPv6, etc.
- **Protocol check** uses the parsed `protocol` property (normalized by the URL spec to lowercase with trailing colon), not a regex on the original string. This is more robust than prefix matching because the URL constructor normalizes before we check.
- **try/catch** is the standard pattern for URL validation — the constructor throws TypeError for invalid URLs.
- **No `finally` block needed** — nothing to clean up.
