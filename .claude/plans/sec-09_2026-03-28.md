# SEC-09: Support Environment Variables for Backend Config Credentials

**Date:** 2026-03-28
**Severity:** Medium | **OWASP:** CWE-798 (Hardcoded Credentials)
**Affected files:**
- `backend/index.ts` (lines 564-586)
- `backend/types.ts` (lines 118-123, `MysqlSettings` interface)
- `.gitignore` (line 1)

---

## Problem Statement

Database credentials (host, user, password, database) are loaded exclusively from `backend/config.json` as plaintext JSON. While `config.json` is listed in `.gitignore`, there are several risks:

1. **Accidental git commit:** A developer might force-add the file (`git add -f`), use a different git client that ignores `.gitignore`, or copy the project without preserving gitignore rules. Once committed, credentials are in history permanently.

2. **No environment variable support:** Standard deployment practice is to pass sensitive values via environment variables (12-factor app methodology). The current code offers no alternative to the plaintext config file.

3. **No startup warning:** If `config.json` is somehow not covered by `.gitignore` (e.g., the gitignore entry is `backend/config.json` but the actual pattern is just `config.json` at root level), there is no runtime check to warn the operator.

### Current Code (index.ts:564-586)

```typescript
const configPath = path.join(__dirname, 'config.json');
let config: Config;
try {
    const configFile = await fs.readFile(configPath, 'utf-8');
    config = JSON.parse(configFile) as Config;
    if (!config.mysqlSettings || !config.gallerySettings) {
        throw new Error('Missing required config fields: mysqlSettings or gallerySettings');
    }
    if (!config.mysqlSettings.host || !config.mysqlSettings.user || !config.mysqlSettings.database) {
        throw new Error('Missing required mysqlSettings fields: host, user, or database');
    }
    // ...
} catch (error) {
    console.error('Error loading config.json:', error);
    process.exit(1);
}
```

The `MysqlSettings` interface in `types.ts` defines:

```typescript
interface MysqlSettings {
    host: string;
    user: string;
    password?: string;
    database: string;
}
```

The config object is passed directly to `mysql.createConnection(config.mysqlSettings)` at line 586, so the `MysqlSettings` shape must remain compatible with the `mysql2` `ConnectionOptions` type.

### Gitignore Coverage

The `.gitignore` contains `config.json` at line 1 (root-level pattern). This matches `config.json` at the repository root AND `backend/config.json` because git applies root-level gitignore patterns recursively. However, this protection is fragile — it depends on developers not circumventing it.

### Security Context

Per CLAUDE.md: "The backend is a one-shot admin tool, not a running server. Security concerns about the backend code are low-impact since it runs locally by a trusted admin." This lowers the severity but does not eliminate the risk — credentials in git history are a real concern even for admin tools.

#### Task 1.1.4: Identify the environment variables to support
Define the mapping:

| Environment Variable | Config Field | Required | Default |
|---------------------|-------------|----------|---------|
| `MYSQL_HOST` | `mysqlSettings.host` | Yes (if not in config) | none |
| `MYSQL_USER` | `mysqlSettings.user` | Yes (if not in config) | none |
| `MYSQL_PASSWORD` | `mysqlSettings.password` | No | none |
| `MYSQL_DATABASE` | `mysqlSettings.database` | Yes (if not in config) | none |

Environment variables take precedence over `config.json` values when set. This means:
- If `MYSQL_PASSWORD` is set, it overrides `config.mysqlSettings.password` even if the config file has a password
- If `MYSQL_HOST` is set but `config.json` is missing entirely, the script should still work as long as all required fields are provided via env vars
- Non-sensitive config fields (`gallerySettings`, `thumbPrefix`, etc.) remain config-file-only — no env var support needed

### Section 1.2: Design Decisions

#### Task 1.2.1: Decide on config.json requirement
When environment variables provide all required MySQL fields, `config.json` should still be required for `gallerySettings` and other extraction settings. The config file remains the primary configuration mechanism; environment variables are an **overlay** for sensitive credential fields only.

Specifically:
- `config.json` is always loaded first (if it exists)
- Environment variables override `mysqlSettings` fields when set
- If `config.json` does not exist but all required fields are available (MySQL via env vars, but `gallerySettings` has no source), the script fails with a clear error

This keeps the implementation simple and avoids duplicating every config field as an env var.

#### Task 1.2.2: Decide on gitignore warning approach
Add a startup check that verifies `config.json` is covered by `.gitignore`. The check should:
- Only run when `config.json` exists on disk (no warning if env-vars-only mode in the future)
- Use `git check-ignore` command to verify the file is actually ignored by git
- Fall back to a simple `.gitignore` file content check if `git` is not available
- Print a `console.warn` warning, not a fatal error (the script should still run)
- Only warn once at startup, not repeatedly

## Phase 2: Implementation

### Section 2.1: Add Environment Variable Override Logic

#### Task 2.1.1: Create `applyEnvOverrides()` helper function
Add a new function in `backend/index.ts`, placed above the main IIFE (above line 563). This function takes the parsed config and returns a modified copy with environment variable overrides applied.

```typescript
/**
 * Override mysqlSettings fields with environment variables when set.
 * Environment variables take precedence over config.json values.
 * Only non-empty string values are treated as overrides.
 */
function applyEnvOverrides(config: Config): Config {
    const envHost = process.env.MYSQL_HOST?.trim();
    const envUser = process.env.MYSQL_USER?.trim();
    const envPassword = process.env.MYSQL_PASSWORD;
    const envDatabase = process.env.MYSQL_DATABASE?.trim();

    const hasAnyEnvOverride = envHost || envUser || envPassword !== undefined || envDatabase;

    if (!hasAnyEnvOverride) {
        return config;
    }

    const overridden: string[] = [];
    const mysqlSettings = { ...config.mysqlSettings };

    if (envHost) {
        mysqlSettings.host = envHost;
        overridden.push('host');
    }
    if (envUser) {
        mysqlSettings.user = envUser;
        overridden.push('user');
    }
    if (envPassword !== undefined) {
        mysqlSettings.password = envPassword;
        overridden.push('password');
    }
    if (envDatabase) {
        mysqlSettings.database = envDatabase;
        overridden.push('database');
    }

    if (overridden.length > 0) {
        console.log(`MySQL config overridden by environment variables: ${overridden.join(', ')}`);
    }

    return { ...config, mysqlSettings };
}
```

Key design choices:
- `MYSQL_PASSWORD` is checked with `!== undefined` rather than truthiness, because an empty password is valid (empty string should override a non-empty config value)
- Other fields use truthiness checks (empty host/user/database are not valid)
- `.trim()` on host/user/database to avoid whitespace-only values
- No `.trim()` on password (whitespace in passwords is intentional)
- Returns a new config object (no mutation of the input)
- Logs which fields were overridden (without logging the values)

#### Task 2.1.2: Integrate `applyEnvOverrides()` into the config loading flow
Modify the config loading section in the main IIFE (lines 564-583). Insert the env override call after config parsing and before validation:

Before (current):
```typescript
config = JSON.parse(configFile) as Config;
if (!config.mysqlSettings || !config.gallerySettings) {
    throw new Error('Missing required config fields: mysqlSettings or gallerySettings');
}
if (!config.mysqlSettings.host || !config.mysqlSettings.user || !config.mysqlSettings.database) {
    throw new Error('Missing required mysqlSettings fields: host, user, or database');
}
```

After:
```typescript
config = JSON.parse(configFile) as Config;
if (!config.mysqlSettings || !config.gallerySettings) {
    throw new Error('Missing required config fields: mysqlSettings or gallerySettings');
}
config = applyEnvOverrides(config);
if (!config.mysqlSettings.host || !config.mysqlSettings.user || !config.mysqlSettings.database) {
    throw new Error('Missing required mysqlSettings fields: host, user, or database');
}
```

The env override is applied **after** the structural validation (mysqlSettings object must exist in config.json) but **before** the field-level validation (host/user/database must be truthy). This means:
- `config.json` must always have the `mysqlSettings` and `gallerySettings` objects
- Individual MySQL fields within `mysqlSettings` can be empty/missing in config.json if provided via env vars
- The validation at the end catches the case where neither config nor env provides a required field

### Section 2.2: Add Gitignore Warning

#### Task 2.2.1: Create `checkConfigGitignore()` helper function
Add a function that checks whether `config.json` is protected by `.gitignore`. Place it above the main IIFE, near `applyEnvOverrides()`.

```typescript
/**
 * Warn if config.json exists but is not covered by .gitignore.
 * Uses `git check-ignore` for accuracy, falls back to .gitignore text scan.
 * Non-fatal: logs a warning and continues.
 */
async function checkConfigGitignore(configPath: string): Promise<void> {
    try {
        await fs.access(configPath);
    } catch {
        return; // config.json doesn't exist, nothing to warn about
    }

    const { execFile } = await import('child_process');
    const { promisify } = await import('util');
    const execFileAsync = promisify(execFile);

    try {
        // git check-ignore exits 0 if file is ignored, 1 if not ignored
        await execFileAsync('git', ['check-ignore', '-q', configPath]);
        // Exit code 0: file is ignored, all good
    } catch (gitError: unknown) {
        const err = gitError as { code?: number | string };
        if (err.code === 1 || (typeof err.code === 'string' && err.code !== 'ENOENT')) {
            // Exit code 1: file is NOT ignored by git
            console.warn(
                '\n⚠  WARNING: backend/config.json is NOT covered by .gitignore.\n' +
                '   This file contains database credentials and should never be committed.\n' +
                '   Add "config.json" to .gitignore or use environment variables instead.\n'
            );
        }
        // ENOENT means git is not installed; skip check silently
    }
}
```

Note: This uses `child_process.execFile` (not `exec`) to avoid shell injection. The `configPath` argument is passed as an array element, not interpolated into a shell string.

#### Task 2.2.2: Call `checkConfigGitignore()` at startup
Add the call immediately after the `console.log('Loading config...');` line, before config file reading:

```typescript

```

The check runs before config loading so the warning appears even if config loading subsequently fails for other reasons.
