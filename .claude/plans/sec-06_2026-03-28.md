# SEC-06: Fix Symlink Bypass in verifyImagePaths.ts Local File Verification

**Date:** 2026-03-28
**Severity:** High | **OWASP:** CWE-22 (Path Traversal)
**Affected files:**
- `backend/verifyImagePaths.ts` (lines 206-227)
- `backend/verifyImagePaths.test.ts`

---

## Problem Statement

`verifyLocalFile()` checks whether a URL-derived local file path stays within the `frontend/public/` directory using `path.resolve()` + `path.relative()` string comparison. This check is insufficient because symlinks can bypass it: a symlink inside `frontend/public/` can point to any location on the filesystem, and `path.resolve()` does not follow symlinks — it only resolves `.` and `..` segments lexically.

### Current Code (lines 206-227)

```typescript
async function verifyLocalFile(
    url: string,
    projectRoot: string,
): Promise<{ ok: boolean; error?: string }> {
    if (!url || typeof url !== 'string' || !url.startsWith('/')) {
        return { ok: false, error: 'Not a local path' };
    }
    const relativePath = url.replace(/^\//, '').replace(/\//g, path.sep);
    const localPath = path.join(projectRoot, 'frontend', 'public', relativePath);
    const resolved = path.resolve(localPath);
    const publicDir = path.resolve(projectRoot, 'frontend', 'public');
    const rel = path.relative(publicDir, resolved);
    if (rel.startsWith('..') || path.isAbsolute(rel)) {
        return { ok: false, error: 'Path escapes public directory' };
    }
    try {
        await fs.access(resolved);
        return { ok: true };
    } catch {
        return { ok: false, error: 'File not found' };
    }
}
```

### Attack Scenario

1. An attacker (or compromised Gallery 2 database) includes a path like `/g2data/albums/legit-looking/photo.jpg` in album JSON data.
2. The directory `frontend/public/g2data/albums/legit-looking/` contains a symlink `photo.jpg -> /etc/passwd` (or any sensitive file).
3. `path.resolve()` resolves `frontend/public/g2data/albums/legit-looking/photo.jpg` — this passes the string-based containment check because lexically it is within `frontend/public/`.
4. `fs.access(resolved)` follows the symlink and reports the file exists.
5. The function returns `{ ok: true }`, confirming a path that actually points outside the public directory.

### Security Context

This is a backend admin tool (not internet-facing), so the practical risk is limited. However, the function's purpose is path containment verification — if it doesn't actually verify containment, it provides false assurance. The fix is straightforward and makes the function correct.

### Fix Strategy

Use `fs.realpath()` to resolve symlinks on both the target path and the public directory before performing the containment check. `fs.realpath()` resolves all symlinks, `.`, and `..` components to the actual filesystem path. The containment check then uses `realPath.startsWith(realPublicDir + path.sep)` (with separator suffix to prevent prefix-matching attacks like `/public-extra/` matching `/public`).

The file must exist for `fs.realpath()` to succeed. If the file doesn't exist, `fs.realpath()` throws, which we catch and report as "File not found" — the same behavior as the current code's `fs.access()` failure path.


`fs.realpath()` resolves all symlinks and returns the canonical absolute path. If the path does not exist, it throws `ENOENT`. This is the correct API for symlink-aware path resolution.

#### Task 1.1.4: Consider edge case — publicDir itself is a symlink
If `frontend/public/` is itself a symlink (e.g., in development setups), we must also resolve `publicDir` with `fs.realpath()`. Otherwise, `realPath.startsWith(publicDir)` would fail because `publicDir` contains the symlink name while `realPath` contains the symlink target.

Both paths must be resolved through `fs.realpath()` for a correct containment check.

#### Task 1.1.5: Consider edge case — path prefix matching
A naive `startsWith()` check like `realPath.startsWith(realPublicDir)` is vulnerable to prefix attacks. If `realPublicDir` is `/workspace/frontend/public`, then a file at `/workspace/frontend/public-extra/secret.txt` would pass because `"/workspace/frontend/public-extra/secret.txt".startsWith("/workspace/frontend/public")` is `true`.

Fix: Check `realPath.startsWith(realPublicDir + path.sep)` OR `realPath === realPublicDir`. The separator suffix ensures we match the directory boundary, not just a string prefix. The equality check handles the edge case where the file is the public directory itself (unlikely but correct).

## Phase 2: Implementation

### Section 2.1: Rewrite verifyLocalFile with fs.realpath()

#### Task 2.1.1: Replace the containment check logic
**File:** `backend/verifyImagePaths.ts`, function `verifyLocalFile` (lines 206-227)

Replace the current implementation with:

```typescript
async function verifyLocalFile(
    url: string,
    projectRoot: string,
): Promise<{ ok: boolean; error?: string }> {
    if (!url || typeof url !== 'string' || !url.startsWith('/')) {
        return { ok: false, error: 'Not a local path' };
    }
    const relativePath = url.replace(/^\//, '').replace(/\//g, path.sep);
    const localPath = path.join(projectRoot, 'frontend', 'public', relativePath);

    // Resolve the public directory to its real path (follows symlinks)
    let realPublicDir: string;
    try {
        realPublicDir = await fs.realpath(
            path.resolve(projectRoot, 'frontend', 'public'),
        );
    } catch {
        return { ok: false, error: 'Public directory not found' };
    }

    // Resolve the target path to its real path (follows symlinks)
    let realPath: string;
    try {
        realPath = await fs.realpath(localPath);
    } catch {
        return { ok: false, error: 'File not found' };
    }

    // Containment check using real (symlink-resolved) paths
    if (
        realPath !== realPublicDir &&
        !realPath.startsWith(realPublicDir + path.sep)
    ) {
        return { ok: false, error: 'Path escapes public directory' };
    }

    return { ok: true };
}
```

Key changes:
1. **`fs.realpath()` on both paths** — resolves symlinks on the target file and the public directory, preventing symlink bypass in either direction.
2. **Separate try/catch blocks** — distinguishes between "public dir missing" (configuration error) and "file not found" (normal verification failure). These are different error conditions and should produce different messages.
3. **`realPublicDir + path.sep` suffix** — prevents prefix-matching attacks (e.g., `/public-extra/` matching `/public`).
4. **`realPath !== realPublicDir` equality check** — edge case: a URL that resolves to the public directory itself.
5. **Removed `fs.access()` call** — `fs.realpath()` already verifies the file exists (it throws `ENOENT` otherwise), so the separate `fs.access()` is redundant.

Confirm that `fs` (from `fs/promises`) already provides `realpath()`. The existing import on line 7:
```typescript

```
This import exposes `fs.realpath()`. No additional imports needed.
